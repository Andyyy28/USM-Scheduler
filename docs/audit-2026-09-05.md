# Scheduler reliability audit and GA-v6 development validation

This audit uses synthetic fixtures only. It preserves the thesis comparison
protocol, shared independent validator/scorer, approved objective weights,
fixed 50-student policy, seeds, and equal-budget pilot design. These checks are
software-development evidence, not an authorized-term thesis conclusion.

## Baseline and changes

The checkout was fast-forwarded from `52292bd` to GitHub's `99df0e1` before
implementation. The complete baseline source archive is retained locally at
`experiment-results/audit-ga-v6/baseline.zip`; historical GA-v5 evidence remains intact.

| Area | Defect and resulting behavior |
|---|---|
| Release pipeline | GitHub rejected the workflow at line 72 because an unquoted shell command contained YAML's colon-space separator. The command now uses a block scalar, and pushes to the thesis branch trigger CI. |
| Dependencies | The audit reported CVE-2026-73228 and CVE-2026-73229 against REST framework 3.16.1. Runtime inputs, lock, and verified hashes now use 3.17.2. The updated lock audit reports no known vulnerabilities. |
| Review history | A unique endorsement constraint prevented endorsement after a subsequent changes-requested decision. Migration 0007 removes that constraint; approval still uses the latest decision. Reviews lock/reload the schedule before accepting a decision and are read-only in administration. Assignment edits/deletions lock and reload their parent schedules, preventing stale draft objects from changing a timetable after review starts. |
| PostgreSQL | Run and formal-study row locks now specify the target row, avoiding unsupported locks on nullable outer-joined relations. Parent batch locks remain explicit. |
| Timetables | UI and exports resolve end times from the persisted room/start against frozen candidates, so a valid draft edit cannot display an old allocation's end time. Active locks match the exact placement. Assignment relations are batch-loaded and the silent 2,000-row cutoff is removed. |
| Run workflow | Filters use stored status/algorithm values before applying the history limit. Failed, infeasible, and timeout results receive recovery guidance. Archived timetables do not offer unsupported export/lock actions, and comparison requires distinct runs. |
| CP-SAT correctness | Legacy snapshots no longer incorrectly receive schema-1.2 daily limits. Rejected independent incumbents produce an implementation error instead of a misleading timeout. Implementation identifier: `cp-sat-v4`. |
| GA tuning | Candidate ranking is consumed lazily and checks deadlines; disabled faculty preferences remain neutral in repair, swaps, and feasible improvement. Existing 128-request repair and 64-trial improvement caps remain. Implementation identifier: `ga-v6`. |
| Benchmark integrity | An archived entrypoint binds its own archived neighborhood module, while validation/scoring remain common. Reports verify both solver files, shared source, inputs, configuration, and environment. `--baseline ga-v5` supports explicit comparisons. |

REST framework's [official 3.17.2 release notes](https://www.django-rest-framework.org/community/release-notes/#3172)
describe the request-body size enforcement and renderer disclosure fixes.

## Verification

The pre-change non-browser baseline passed 295 tests. The final non-browser suite
passed **315 tests**, with 3 opt-in tests deselected and **86.36% coverage**.
Ruff, Django configuration and production security checks, migration drift,
dependency consistency, locked dependency audit, and static collection passed.
Local migrations 0006 and 0007 applied successfully after a SQLite backup.

Local Chromium launch fails with `BrowserType.launch: spawn UNKNOWN`, before
application assertions. Local Docker is unavailable. CI therefore runs the full
browser suite on Linux/PostgreSQL and builds/starts the disposable Compose stack.
Its `check_runtime --confirm-empty-database` command refuses populated databases,
requires real queued execution, runs both solvers in a separate worker container,
and independently validates the persisted schedules. This is separate from actual
worker-loss recovery testing and formal benchmark resource acceptance.

## Reproduction

Use the project's Python 3.12 environment. Extract both `genetic.py` and
`neighborhood.py` from baseline commit `99df0e1` together before comparing.

```powershell
git archive --format=zip --output=experiment-results/audit-ga-v6/baseline.zip 99df0e1
Expand-Archive -LiteralPath experiment-results/audit-ga-v6/baseline.zip -DestinationPath experiment-results/audit-ga-v6/baseline
python scripts/compare_ga.py --output experiment-results/audit-ga-v6/validation --source ga-v5=experiment-results/audit-ga-v6/baseline/scheduler/solvers/genetic.py --source ga-v6=scheduler/solvers/genetic.py --budgets 30 --seeds 5001 5002 5003 5004 5005 --cases moderate_mixed tight_contention daily_limit_stress unseen_dense unseen_daily
python scripts/report_ga_comparison.py experiment-results/audit-ga-v6/validation --baseline ga-v5 --output experiment-results/audit-ga-v6/validation-report.json
```

Run timed observations serially on the same host without other solver workloads.
Preserve every seed, failed observation, source hash, witness, and penalty regression.
The development harness uses population 40; it does not select a formal profile.
Both registered equal-budget synthetic pilots must be rerun for the final solver
build before authorized-term experiments. Institutional data, formal inference,
physical-device acceptance, and production deployment are outside this pass.

## Completed 30-second development comparison

All 50 saved observations passed independent revalidation. Both GA-v5 and GA-v6
were feasible in **25/25** runs. GA-v6 produced lower penalties in **15** pairs,
equal penalties in **5**, and higher penalties in **5**.
There were no feasibility losses. These are synthetic development results only.

| Scenario | GA-v5 median penalty | GA-v6 median penalty | Feasible, each version |
|---|---:|---:|---:|
| moderate_mixed | 241 | 209 | 5/5 |
| tight_contention | 446 | 421 | 5/5 |
| daily_limit_stress | 33 | 33 | 5/5 |
| unseen_dense | 414 | 315 | 5/5 |
| unseen_daily | 161 | 159 | 5/5 |

The [machine-readable evidence](evidence/algorithm/ga-v6-development.json) records
all observations, hashes, paired regressions, and timing limits. Median first-feasible
time on tight contention changed from 3.516 s to 1.969 s; on the dense holdout,
from 7.734 s to 5.688 s. Windows timing is quantized and host-dependent, so these
are descriptive development measurements rather than formal speed claims.
